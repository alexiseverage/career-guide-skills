# Optional aesthetic

Offer the choice once per task, including when the reader requests both outputs. For example, “Would you like a named visual style or the default low-ink design?” Treat a named style already in the request as an opt-in. If the reader declines, asks for no questions, or is unavailable and has given no style preference, continue with the default print design.

After opt-in, use [Aesthetic Frontend Skills](https://github.com/alexiseverage/aesthetic-frontend-skills) if available. Use `aesthetic-literacy` to resolve the style and `aesthetic-application` to identify the parts transferable to print. If the collection is missing, offer to install it with permission, or show the reader the project-scope command.

```sh
npx skills add alexiseverage/aesthetic-frontend-skills
```

The command lets the reader select the two skills and target agent. Install only in the agreed scope and reload the skills if the host requires it. If installation is declined or unsupported, continue with available design references and the reader's style brief.

Translate the chosen style through type hierarchy, a light accent treatment, rule shapes, and restrained motifs. Give primary content dark text on light paper. Keep section identity legible in grayscale through labels and type. Preserve binding margins, writing space, page count, and source readability. Omit motion, full-bleed backgrounds, and large dark fills from the print version.
